# TV2: sửa nộp bot và đấu thử

Nhánh local: `bot-engine-sandbox`. Không triển khai tài khoản/đội TV1.

## Chạy sau cập nhật

1. `pnpm db:generate`
2. `pnpm db:migrate` — thêm `BotTestRun.extraType`, giữ dữ liệu hiện có.
3. Khởi động lại API, web và worker (`pnpm dev`, terminal khác: `pnpm dev:worker`).

API cần Python 3 để phân tích AST, không thực thi mã nộp trong lúc kiểm tra cú pháp.
Nếu `python` không trỏ đúng bản cài, đặt `PYTHON_CMD` thành đường dẫn Python.
Nhãn “Hợp lệ” là hợp lệ cú pháp/giao diện; hãy đấu thử để kiểm tra hành vi.

## Môi trường chạy bot

Mặc định bot Python chạy trong Docker. Cần Docker Linux containers đang hoạt động và tải image trước:

```sh
docker pull python:3.13-slim
```

Có thể đặt `BOT_SANDBOX_IMAGE` sang image đã duyệt/pin digest. Runner không tự pull.
Container không có mạng, bỏ capabilities, chạy user không đặc quyền, root filesystem chỉ đọc,
chỉ mount thư mục bot tạm ở chế độ chỉ đọc; RAM/swap 128 MiB, PID 32,
tmpfs 16 MiB, tổng stdout/stderr tối đa 1 MiB. CPU quota theo tỷ lệ ngân sách CPU/wall;
đây là quota cgroup, không phải phép đo CPU chính xác cho từng lượt. Timeout wall vẫn áp dụng.
Worker cần quyền Docker; nên chạy trên máy/VM riêng khi nhận mã không tin cậy.

Nếu chỉ demo bot do chính nhóm viết trên máy chưa có Docker, đặt rõ trong `.env`:

```dotenv
BOT_SANDBOX_MODE=trusted-local
```

Chế độ này không cách ly file/mạng/RAM và không dành cho bot của người ngoài.
Không tự chuyển sang local nếu Docker lỗi. Bot mẫu mô phỏng không cần Python/Docker.
Lỗi hạ tầng Docker là lỗi lượt chạy, không xử người chơi thua do bot.

`.env.example` chọn `trusted-local` cho demo cá nhân. Worker kiểm tra Python hoặc Docker/image
ngay lúc khởi động và báo rõ chế độ đang chạy. `.env` trên máy hiện tại đã được cấu hình local.

## Các thay đổi

- Gửi JSON đúng content type cho nộp bot và đấu thử; hiện lỗi API trên hộp thoại.
- Dialog không còn animation ghi đè transform căn giữa; hỗ trợ cuộn ở màn hình thấp.
- Button mặc định `type=button`; nút submit khai báo riêng.
- BTC nhập ID đội thật, không dùng đội giả; giới hạn nhãn 100 ký tự.
- Body JSON tối đa 4 MiB để chứa source 500.000 ký tự kể cả JSON escaping.
- AST kiểm tra cú pháp và hàm đồng bộ `make_move(state)`, chạy bất đồng bộ có timeout.
- Cấp số phiên bản trong transaction, khóa theo đội; không đọc max/version ở service.
- Kiểm tra quyền bot đối thủ, bot mẫu, trạng thái hợp lệ và ID; lỗi input trả 400.
- Lưu trận thử và outbox cùng transaction; phát lại khi Redis phục hồi, quét job mất.
- Worker đánh dấu đúng bản ghi đấu thử khi hết retry; lưu lựa chọn quân thứ 10.
- Lỗi import/khởi động bot được xử thua và lưu lý do; lỗi giữa ván có log.
- Đọc stderr để tránh deadlock, giới hạn output, dọn container khi kết thúc.
- Giới hạn 10 lần nộp/đấu thử mỗi phút mỗi đội trên một API instance.

## Kiểm thử

- `pnpm test`, `pnpm build`, `pnpm typecheck`.
- Khởi động web, chạy `pnpm exec playwright test --config tests/ui/playwright.config.ts`.
  Test UI dùng API mô phỏng, kiểm tra màn hình 1100×500, nộp bot, đấu thử bot mẫu và lỗi API.
- Unit test runner dùng các fixture tin cậy với `trusted-local`; không chứng minh Docker isolation.
- Cần kiểm thử tích hợp PostgreSQL/Redis và Docker trên máy đã cài các dịch vụ đó trước khi nhận bot ngoài nhóm.

### Kiểm chứng quy trình thật trên máy demo

Đã chạy `tests/live/bot-submission.spec.ts` với web/API/worker và PostgreSQL/Redis đang hoạt động,
không mock API: đăng nhập Nguyễn An, đấu thử Alpha v2, nộp bot Python greedy, đấu thử bot vừa nộp.
Bot nộp được lưu v5; trận `cmvkoh3yn0007f1gke0cuz6ao` hoàn thành 120 nước, kết thúc `eliminate`.
Chế độ thực thi được kiểm chứng là `trusted-local`; Docker isolation chưa kiểm chứng trên máy này.

Chạy lại khi các dịch vụ đã mở:

```sh
pnpm exec playwright test --config tests/live/playwright.config.ts
```

Test này tạo một phiên bản bot và các lượt đấu thử mới trong database demo, không xóa dữ liệu cũ.
